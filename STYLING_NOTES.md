# Styling notes

Stack: **Tailwind CSS v4** for layout, spacing, typography and flat colors, and **SCSS** (modules + `@use`) for the Windows XP chrome that utilities express badly: gradients, two-tone bevels, multi-layer shadows, pseudo-elements, animations and interaction states. Tailwind's Preflight reset is deliberately not loaded, because it would restyle every native button and heading and break the XP look.

## 1. Where tokens live and how they flow

```
frontend/app/styles/_tokens.scss      single source of truth (SCSS maps)
        │
        ├─ @use "tokens" as t  ───────►  every component .scss: t.color(blue), t.radius(sm), t.shade(.25)
        │
        └─ xp-theme.scss (@each)  ────►  :root { --xp-blue: #245edb; --xp-font-size-md: 13px; … }
                                                │
frontend/app/tailwind.css  @theme inline  ◄─────┘  --color-xp-blue: var(--xp-blue) → bg-xp-blue, text-xp-md, p-xp-sm, rounded-xp-sm
```

- Values exist only in `_tokens.scss`. `tailwind.css` maps names, never values.
- The color block in `tailwind.css` is generated by `npm run tokens:sync`, and `npm run tokens:check` fails if a token has no Tailwind mapping ([scripts/sync-tokens.mjs](frontend/scripts/sync-tokens.mjs)).
- `@theme` resets Tailwind's default palette, sizes and radii (`--color-*: initial`). Only design-system classes compile: `bg-red-500` does not exist.
- `sassOptions.loadPaths` in [next.config.ts:16](frontend/next.config.ts#L16) lets any stylesheet write `@use "tokens"` / `@use "mixins"`.
- Accessors fail the build on typos ([_tokens.scss:217](frontend/app/styles/_tokens.scss#L217)): `t.color(bleu)` is a compile error, not a silent blank.

## 4. Honest gaps

- **Unused primitives:** `XPButton` and `XPPanel` are converted but have no consumers, so they are not claimed above.
- **Unstyled game dialogs:** Matchmaking, OpponentDisconnected, Rematch, Rules and FriendInvite have no styles at all; they render browser-default content inside `XPModal`. Most dialog buttons are native `<button>`s, not `XPButton`. Switching them would change the look, so it wasn't done.
- **One-off font sizes:** seven sizes are arbitrary Tailwind values (`text-[15px]`, `[17px]`, `[19px]`, `[21px]`, `[25px]`, `[26px]`, `[64px]`), not tokens.
- **Breakpoints:** they are ad-hoc numbers (420–1100px), not tokens. Tailwind's `max-[Npx]` means `width < N`, where the old CSS meant `≤ N`, so it differs only at exactly N px.
- **Chart colors:** the Recharts line colors (`#008000`, `#cc0000`) stay in JS, because SVG attributes can't read CSS variables.
- **Leaderboard gap:** the left column has no gap because `leaderboard.tsx` uses an undefined `styles.podium`. That look was preserved, not fixed.
- **Pre-existing issues, not styling, left untouched:**
  - `next build` fails at type-check on `app/chats/page.tsx:23` (`user` possibly null), on `main` too.
  - eslint reports 97 problems (98 on `main`).
  - `AuthRedirect` sends logged-out users away from `/forgot-password` and `/reset-password`.
  - `StartMenu`'s `onClose` prop is unused.
